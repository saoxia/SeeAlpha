# 项目操作记录 API

2026-10-27：操作记录属于 SeeAlpha，列表只读项目持久化账本。
Binance 是外部证据来源之一，不是页面查询时透传的响应。
当前接入 Binance USD-M 永续及期权只读操作证据；手动交易是独立入口，见 [手动交易](MANUAL_TRADING.md)。

## 接口

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| GET | `/api/operations` | 登录用户；筛选并分页查询统一记录 |
| GET | `/api/operations/{id}` | 登录用户；查询投影及原始观察证据；合并前的旧 ID 仍可解析 |
| POST | `/api/operations/sync` | 管理员；通过 Nautilus 原生节点补充交易所证据 |
| GET | `/api/operations/export` | 登录用户；按相同筛选条件导出项目记录 CSV |

查询支持 `account_id`、`environment`、`strategy_id`、`source`、`event_type`、
`symbol`（品种标识包含匹配）、`start_ms`、`end_ms`（毫秒，包含边界）、`limit`（1–500）、`cursor`。
返回 `records`、`next_cursor`、`has_more`、`warnings`、`sync`。
游标包含时间和稳定记录 ID，作为不透明字符串原样传回，翻页时保留相同筛选条件。

记录保留 `account_id`、`environment`、`exchange`、`symbol`、`event_type`、`timestamp`、
`client_order_id`、`order_id`、`trade_id`、`strategy_id`、`source`、`confirmed`、
数量、价格、手续费及状态。金额使用十进制字符串。当前原生品种标识例如 `ETHUSDT-PERP`。

`source`：

- `project`：有本项目操作证据，可关联策略；没有交易所确认时 `confirmed=false`。
- `external`：交易所存在、项目尚无归属证据；不能自动认定为手工。
- `reconciliation`：项目运行时明确记录的对账修正，不是真实成交。

`event_type`：`place`、`amend`、`cancel`、`fill`、`reject`、`expire`、`correction`、`cashflow`。
交易所导入的 `place` 表示存在该订单及其状态，不保证能够重建全部下单、改单过程。

同步请求 JSON 可包含 `account_id`、`start_ms`、`end_ms`。
未指定账户时遍历当前配置账户；默认最近 24 小时，起点须在最近 87 天内。
不支持的账户、网络错误、解析缺口会反映为账户同步失败，已有记录保留。
API 进程默认启动每 300 秒一次的同步循环，`OPERATION_SYNC_SECONDS=0` 可关闭。
当前实现保守地将交易所历史标为 `complete=false`；后台运行不代表历史完整。

## 记录与关联

`api/operations/repository.py` 提供后端 `Operations.ingest(Observation)`，不向浏览器开放
伪造策略来源的写入端点。项目事件可以先于交易所确认入库，拒绝和失败操作可保留。

- 按账户、环境、交易所、品种隔离身份。
- 真实成交通过 `trade_id` 去重，多笔部分成交分别保留。
- 使用 `client_order_id` 与交易所 `order_id` 关联。迟到的映射会合并重复投影，保留详情别名。
- 有项目发起操作的证据后，可将同订单已导入的外部成交关联到策略；单纯策略认领不作为发起证据。
- 同一订单出现冲突策略归属时拒绝写入，不自动选择归属。
- 每个观察事件内容不可改写；相同事件重试幂等，同一事件 ID 携带不同内容时拒绝。
- 投影可随新证据更新；交易所已确认的金额字段不被迟到的项目请求覆盖。
- 通用 ORM 路径在账户、环境、交易场所和交易品种范围内持有事务锁，完成合并、证据写入及来源更新。

## Nautilus 接入边界

本机 `nautilus-trader==2.0.0rc7` 的 Rust 执行对账支持原始报告，但 Python 通用消息
订阅不能接收这些原生类型（会报告 `non-PyMessage`）。本轮实际验证使用公开
`LiveNode.cache.orders()` 和订单执行事件读取，未调用私有 HTTP 客户端或 CCXT。

读取节点仅作查询，不安装下单策略，不修改杠杆和保证金。
原生对账创建的临时合成仓位订单会排除；仅保留具有 Binance 数字成交 ID 的真实成交。
状态报告推断的成交不视为真实成交。公开缓存投影不能替代完整的原始报告审计链，
交易所保留期、可发现品种、接口截断和 Python 暴露范围都可能造成历史缺口。

项目执行运行时可使用 `OperationService.record_project_event(event, order, account)`
持久化真实 Nautilus 项目事件，其中 `account` 必须是运行时绑定的业务账户。
`LedgerObserver.capture_event()` 提供事件缓冲，执行进程应在自己的订单事件回调中喂入，
并由工作线程取出 `drain()` 后执行 `Operations.ingest()`；不要在原生执行回调线程进行
网络或数据库 I/O。本轮没有启动实盘策略，也没有将回测事件写入实盘业务账本。
后续实盘执行节点必须显式接入该持久化入口，不能仅依靠短时查询节点恢复策略归属。

## 存储与前端

通用 ORM 将操作记录保存在 `ledger_operations`、`ledger_observations`、
`ledger_aliases`、`ledger_sync`。服务端通过 PostgreSQL 连接访问，应用接口只新增观察证据；
投影合并时可以更新证据关联的 ID。新库与历史库的权限配置各自核对。


本机检查的旧 `operation_records` 为 0 条，无需迁移历史操作。旧 SQLite 表仍保留，
后续不会由新列表读取。其他旧权益、快照、人工资金调整接口不属于本轮范围。

前端实时账户页和数据管理页的操作列表、同步和操作导出均使用新 API。
旧 `/api/exchange-accounts/*/trades` 及 `/api/data-management/operations` 不再由这些页面调用。
账户切换、列表轮询和同时间戳分页使用稳定记录 ID；来源在列表中明确显示。
其他数据集的导出继续使用旧 API。

验证包括 SQLite 并发去重、迟到归属、身份桥接、账户/环境隔离、鉴权、CSV 导出，
实际原生适配器连接本机模拟 Binance，前端路径/来源/轮询合并测试，以及
`tests/sql/operations.sql` 对云端实际 RPC 的回滚事务校验。云端 SQL 测试不留下演示记录。

本轮验收：Python 全量 1,355 项、前端 6 项测试通过，Ruff、ESLint 和生产构建通过。
真实前端代理查询、同步、导出与鉴权通过；当前配置账户为 0，尚未使用真实 Binance
私有凭据验收历史同步。

## USD-M 资金流水（2026-10-31）

本节扩展由用户明确要求接入的资金变动；前文验收数字和账户数量为当时记录。
沿用 API → connector → 业务账本的职责与存储边界，不增加数据库表、服务或执行能力。
现有生产库包含 ORM 原先未声明的事件类型检查约束，须经单独授权运行迁移
`3debb89b484a`，在原七种类型之外允许 `cashflow`；保留其他约束、索引和已有记录。
该约束现已同步声明到 ORM。迁移拒绝覆盖未知约束定义，不自动降级或删除资金证据。
锁定版本的 Nautilus Python 公共接口未暴露收支历史查询，因此 connector 的 `income.py`
补充固定 `GET /fapi/v1/time` 与签名 `GET /fapi/v1/income`，不访问适配器私有接口。
生产与 sandbox 凭据分别发往固定的正式和测试主机；禁止重定向，异常不回显签名或凭据。

来源：[Binance Get Income History](https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Get-Income-History)。
该接口只提供近期保留窗口，身份由同一账户、环境、交易所下的 `incomeType + tranId`
确定，不把 `tranId` 当全局唯一，也不以订单号去重。系统保守支持最近 87 天，
不把保留期外的空响应认定为已覆盖历史。

### 证据与展示

- `cashflow` 保存 `income_type`、`transaction_id`（十进制字符串，避免大整数精度损失）、
  `asset`、有正负号的 `amount`、交易所 `timestamp`、可选 `trade_id` 与 `info`。
  `symbol` 保留交易所原值，可为空；不虚构订单、方向、成交价格或策略归属。
- 包含官方返回的资金费、手续费、已实现盈亏、划转、返佣及其他类型；未知类型和零金额仍保留。
  正负号不重新推断，不跨币种相加，不从资金费率估算实际资金费。
- 记录以外部交易所证据写入已有 `ledger_operations` / `ledger_observations`；重复接收幂等，
  同一资金身份内容冲突则拒绝覆盖。账户改名不改变资金身份，原始观察标签保留。
- 成交中的手续费与 `COMMISSION` 收支可能描述同一笔经济事实；未来估值必须明确只记账一次。
  本轮只保存证据，不新增资金余额推算或修改现有账户权益。
- `GET /api/operations?event_type=cashflow`、详情与 CSV 导出均可读取持久化流水；
  账户记录页增加“资金变动”筛选，展示原精度金额、币种、类型和流水号。
  这些记录表示合约钱包变化，不等于已采集现货钱包、链上充值提现或其他产品的全量记录。

### 补齐、恢复与覆盖

沿用每 300 秒的现有同步循环，资金先独立读取，随后运行原生订单同步；订单节点失败
不撤销已保存的资金证据。仍可使用 `OPERATION_SYNC_SECONDS=0` 关闭整个原有循环。
`POST /api/operations/sync` 新增可选 `cashflows_only=true`，仅补齐资金，不启动原生节点；
管理员、会话与来源检查不变。账户记录页按已应用的“资金变动”筛选使用此模式。

首次自动补齐从最近 87 天起点开始；后续从持久化检查点续跑，并重查前 24 小时以吸收迟到记录。
显式 `start_ms/end_ms` 可重查任意受支持区间，较早迟到记录需显式重查，不承诺任意迟到都能自动发现。
超过自动查询窗口的断线缺口保持未覆盖，已有历史证据不删除，不把检查点截断等同于补齐成功。

每个初始请求窗口不超过 7 天；满 1000 条时二分请求时间区间，覆盖所有相同毫秒记录，
不假设响应排序，也不依赖未在当前文档声明的 page/fromId 参数。
单毫秒仍满页、重复身份、越界时间或非法数值均失败；已完成窗口保留，未完成窗口不推进。
GET 请求限速并有限重试，拒绝重定向及永久错误；429 超出有界等待后交由下轮恢复。

`ledger_sync.body.cashflows` 保存 `coverage`（已成功读取并入库的闭区间）、`next_ms`、
`lookback_floor_ms`、最近请求范围、`status`、`requested_complete` 与请求计数。
记录与窗口确认按顺序提交；中途失败可能已保存部分证据，重试通过资金身份去重。
取消或进程中断不会提前确认剩余窗口。不同币种不共享金额累计，环境隔离；部署沿用单 API 同步循环。

`requested_complete=true` 只表示该次请求区间已按端点上限处理完毕，不证明开户以来历史完整、
交易所不再补记、订单历史完整或账户可用于倒推。本次资金流水接入本身不建立基准快照或重放估值。
2026-11-07 后续授权已增加独立资产估值证据与重算，见 [资产估值](EQUITY_VALUATION.md)；
其只覆盖启用后保存的证据，不将既有流水列表改称完整历史。

部署前先停止旧 API，按仓库规范取得数据库迁移授权，再用原数据库配置执行
`.venv/bin/alembic upgrade head`，检查版本后启动 API。程序不会自动修改生产约束。

2026-10-31 本机部署已获得用户明确授权并完成 `3debb89b484a` 迁移；已核实迁移前后原有
账本、观察证据及别名的内容指纹一致，其他检查约束未变。API 已使用原配置重启，
资金流水已开始按上述流程入库；各账户实际补齐进度仍以持久化同步状态为准。

## 期权操作与持仓推算（2026-11-08）

按用户要求，期权持仓采用一次初始持仓基准加后续实际操作推算，不加入首页分钟快照。
沿既有 API → Binance 只读 connector → ORM/SQLite 账本和 `ledger_sync` JSON 实现，
不增加表、迁移、后台服务或交易命令。原 USD-M 余额、估值曲线及风控输入保持不变。

### 操作证据

原操作同步循环（默认每 300 秒）及管理员同步接口增加正式环境 EAPI 查询：

- `/position` 只在尚无初始基准时读取，重启复用已有基准。
- `/openOrders` 发现当前委托和合约；`/historyOrders` 保存最近 5 天内可查询的已完成订单。
  满页保留已读订单并提示生命周期覆盖不足，不把累计成交量伪造为成交。
- `/userTrades` 按已发现合约保存真实成交，保留十进制精度、订单号、成交号和币种，
  手续费按现有账本费用语义转换符号。买卖、减仓和反向开仓由成交数量推动。
- `/bill?currency=USDT` 保存期权资金流水，并发现含合约身份的新合约。
  资金类型以 `OPTIONS_` 为前缀，避免与 USD-M 流水身份冲突；金额仍保留原始正负号。
- `/exerciseRecord` 保存真实行权数量、方向、时间及金额证据。行权数量参与持仓推算；
  操作列表中的行权资金来自 bill，不伪造平仓成交，不重复累计资金。

账本订单和成交继续复用账户、环境、交易所、完整合约代码和真实成交号的幂等身份；
外部证据不认定为项目发起或手动下单。来源冲突与事务保护保持不变。
`cashflows_only=true` 同步两类资金，不获取初始持仓、挂单、订单或成交，不推进期权持仓水位。

### 初始基准与恢复

`ledger_sync.body.options` 保存初始基准、账户凭据指纹、已发现合约、行权证据、
成功水位及派生持仓。建立基准时用交易所时间夹住一次持仓查询；期间发现成交或行权，
仅保存已读操作，不接受有歧义的基准，下轮重新建立。基准时间之前的操作不再次计仓。
正常后续同步只查询操作，重启不重新抓取持仓。凭据变化保留原基准并停止使用，
需要确认账户身份后另行处理，不能静默把不同私有账户的证据混在同一基准。

每次从原始基准与已入库的真实成交、行权重新推算成功覆盖区间，而非在上轮结果上重复加量。
重叠重查最近 24 小时以吸收迟到操作；更早迟到记录需要显式重查。失败保留旧基准、
投影与成功水位，已经入库的操作和行权证据不撤销，下次幂等恢复。
挂单、撤单、拒绝或资金账目均不直接改变持仓数量；无证据的到期持仓不会自动清零。
同毫秒双向成交无法确认均价顺序时保留准确净数量、均价留空。

新操作从 bill、当前挂单、初始持仓、行权及历史已知合约发现。交易所对 bill 的
合约字段可能缺失，未知合约的无成交已撤单也可能无法发现，因此始终提示历史覆盖有限，
不宣称开户以来全部操作完整。合约资金记录缺少合约时，不推进持仓推算；
订单历史仅 5 天，资金/成交按最近三个月保留期保守支持 87 天。
资金、成交与行权查询按七日窗口读取，满页二分时间，单毫秒满页或非法证据不确认覆盖。
成功水位之前出现超出保留期的断线缺口时，保留旧值并明确失败，不自动重设基准。
沿用现有单 API 操作同步部署约定。

### 首页读取

单账户、总览及仓位接口合并读取已持久化的期权推算结果；期权数据不写入
`portfolios/` 分钟文件，也不会随“刷新资产”重新抓取期权持仓。普通页面读取不访问交易所。
首页每分钟重读已保存数据；期权数量更新频率取决于操作同步成功进度。
原生永续余额尚无快照时，已有期权持仓仍可显示。

页面标记期权，显示推算数量、方向及可确认均价；操作记录不能提供当前标记价，
所以期权当前市值、浮盈亏和强平价留空，原始基准价格不冒充当前价格。
期权资产不并入当前 USD-M 账户权益。同步失败、超过十分钟未成功、尚无基准或账户凭据
变化均提示，空列表不等于账户没有真实期权持仓。

官方字段与保留期依据：[期权订单、成交及行权](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-options/api/rest-api/trade)、
[期权资金流水](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-options/api/rest-api/account)。
真实账户权限与线上返回仍需部署后验证，模拟测试不替代真实账户验收。
