# 行情数据管理 API

当前范围为已接入的 Binance USD-M 逐笔 `trades` 日归档、Nautilus `TradeTick` 及派生 K 线。
订阅意图存在业务表 `market_data_policies`。实时接入、历史补齐和 K 线计算进程由
常驻引擎启动（`engine.feed.managed`、`engine.pipeline.pair_data`）；API 不再自行
`Popen` 这两个入口。API 内仍定期做文件监控。不启动实盘策略、不改写研究冻结来源。
前端入口为「数据管理 → 行情数据」，历史与实时状态在同一清单展示；保留账户记录，页面不再提供数据导出。
历史导出路由、任务动作和服务实现保留公共兼容，前端不再创建导出任务或显示下载入口。
行情记录预览也已从列表菜单及详情弹窗移除；`GET /ticks`、`GET /bars` 保留只读公共兼容，
前端不再发起预览请求。删除计划的文件清单预览及确认保护保留。

## 接口

所有路径以 `/api/data` 开头，均要求登录；下表标明管理员专属操作。

| 方法与路径 | 功能 | 权限 |
| --- | --- | --- |
| `GET /capabilities` | 周期、操作权限及范围限制；symbols 保留为空列表，不作为品种白名单 | 登录 |
| `GET /status` | 存储可访问性、可写性、可用字节及任务状态 | 登录 |
| `GET /markets` | Binance 当前 USDT / USDC 永续品种，含原生交易对、base、quote；沿用既有品种缓存 | 管理员 |
| `GET /datasets` | Tick 或指定 `interval` K 线的事件区间；纳秒值以字符串返回 | 登录 |
| `GET /datasets/latest` | 已配置永续交易对的最新 Catalog 1s K 线事件时间；交易对映射至纳秒字符串，无数据为 null | 登录 |
| `GET /coverage` | 按 UTC 日查看归档、CHECKSUM、转换记录与实际 Catalog 文件覆盖 | 登录 |
| `GET /quality` | 查询精确请求范围最近一次历史逐笔校验结果 | 登录 |
| `POST /prepare/plan` | 预览完整 UTC 日归档范围及缺失物化日期，不下载、不写行情 | 管理员 |
| `POST /delete/plan` | 预览所选完整 UTC 日的删除文件清单、大小、依赖清理与快照指纹 | 管理员 |
| `GET /ticks` | 兼容只读逐笔成交查询，支持有界游标分页 | 登录 |
| `GET /bars` | 兼容只读 K 线查询 | 登录 |
| `POST /jobs` | 创建准备、校验、派生、Tick 导出或确认后的删除任务 | 管理员 |
| `GET /jobs` | 最近 100 项数据任务 | 登录 |
| `GET /jobs/{id}` | 任务结果、错误及最后 32 KB 日志 | 管理员 |
| `POST /jobs/{id}/cancel` | 停止所属服务的任务及转换子进程 | 管理员 |
| `GET /jobs/{id}/download` | 下载成功导出任务的 Tick CSV | 管理员 |
| `GET /feed/status` | 当前分钟行情状态，过期 READY 降级 | 登录 |

`GET /datasets?all_levels=true` 从 Catalog 已保存的品种中发现实际存在的 Tick 与 K 线文件区间，不生成预设空行，
每项增加 `level` 标识；不带参数仍查询 Tick，`interval` 仍查询指定 K 线周期，均不再生成预设空行。
`GET /feed/status` 对有效状态文件额外发布白名单字段 `symbols`，每个品种仅含
`next_ms`（连续检查点）及 `last_websocket_ms`（最近实时消息时间）；保留全局过期降级。
缺失或异常文件不会生成模拟订阅状态。前端继续按 `valid_until_ms` 检查时效，
仅对已订阅的 1 分钟数据展示运行状态，不将全局 READY 套用到其他品种或级别。
本轮不增加采集启停、实时 Tick 落盘或跨存储删除。

`GET /coverage`、`GET /quality`、`GET /ticks`、`GET /bars` 使用
`symbol`、`start`、`end`，可选 `interval=1m`。时间须显式带时区，统一为 UTC，采用 `[start,end)`。
历史任务不设固定天数上限，数据必须属于已完成 UTC 日；沿用现有逐日处理、任务互斥和取消。
`GET /capabilities` 的 `max_range_days=null` 表示不设固定跨度上限，保留原字段名。
Tick / Bar 预览仍最多 15 分钟，`limit=1..500`，默认 100，不随历史任务范围放大。
`cursor` 绑定品种、范围、周期和 Catalog 文件指纹；数据变化后游标失效，须重新查询。
同一纳秒多笔成交保留，不以时间戳去重；纳秒、价格与数量均以字符串传输，避免浏览器数值精度损失。

`intervals=[]` 明确表示只准备 Tick；`intervals=["1m"]` 同时准备底层 Tick 和 1 分钟 K 线。
省略 intervals 继续沿用既有默认 1m，既有多周期 API 请求仍支持。前端仅选择一个级别；
K 线生成任务不接受空周期。`GET /datasets?interval=1m` 查看该周期，无 interval 则查看 Tick。

任务请求示例：

```json
{
  "action": "prepare",
  "symbol": "ETHUSDT",
  "start": "2026-08-01T00:00:00Z",
  "end": "2026-08-02T00:00:00Z",
  "intervals": ["1m"]
}
```

计划接口使用相同字段，但不传 `action`。成功创建任务返回 `202` 和任务编号。
不存在的任务返回 `404`，并发冲突返回 `409`，无效范围返回 `422`，存储或任务数据库不可用返回 `503`。

## 操作及完成语义

- `prepare`：复用 `prepare_data()`，同步官方归档及 CHECKSUM、转换 Tick、补齐选定周期并准备特征。
  始终 `force=False`，不自动刷新已有远端归档。按完整 UTC 日处理，不把请求中的局部时段视为单独归档。
- `validate`：只读校验 SHA-256，沿用现有转换器的归档规范化规则，将每个 UTC 日的价格、数量、方向、成交编号和事件时间与 Catalog 逐笔比较。
  重复记录处理遵循现有规范化语义；结论限定为规范化归档与 Catalog 一致，不声称交易所原始归档必然完整。
  任一日期失败，任务失败且保留逐日原因；无成交时段不直接算缺口。
- `materialize`：仅使用本地校验通过的 trades 归档，通过现有转换入口补齐派生 K 线。
  不下载、不强制重建；缺少原始归档或合约定义时失败，先执行数据准备。
- `export`：流式导出所选时间范围内实际存在的 Tick 为 CSV，保持十进制精度，先写临时文件再发布。
  导出成功仅代表文件完成，不代表该范围数据完整或通过质量校验。
- `delete`：仅按完整 UTC 日删除选定品种的数据，同时清理该范围的 Tick、全部已知 K 线周期、
  成交 quote 补充数据、转换/失败记录，以及开始日期及其后的滚动指标文件和元数据。
  后续指标依赖被删除的历史，必须失效；后续 Tick / K 线仍保留。合约定义、账户、操作账本、
  连续分钟行情、导出文件和研究报告保留，报告所依赖的历史数据可能不再可用。
  默认保留 ZIP 和 CHECKSUM；仅当 `delete_archives=true` 时一并删除选定日期的原始文件。

删除请求须先调用 `/delete/plan`（DataRange 字段加可选 `delete_archives`），再向 `/jobs` 提交
相同范围及 `action="delete"`、`deletion_snapshot`（计划返回的 snapshot）和
`confirmation="DELETE ETHUSDT"`（须与实际规范化品种匹配）。服务持锁检查文件快照，worker
执行前再次检查，变化或空范围拒绝执行；不会接收前端指定的文件路径。
拒绝符号链接、无法识别的 Catalog 文件，以及跨越删除日期边界的文件；跨界文件须选择覆盖它的
完整范围。原始数据可能保存在外置盘，执行前必须确认挂载可用。
清理先移除完成记录和依赖指标，避免中断后将剩余不完整数据误认作已完成。
删除不可撤销，不是事务回滚；取消、进程中断或存储错误可能留下部分已删除文件，
任务日志逐文件记录成功删除项，恢复后必须重新预览。文件大小合计不保证等于实际释放空间。

文件覆盖、`recorded_rows` 和准备成功不能替代逐笔校验。
`GET /quality` 和任务详情返回的是历史时点证据；后续数据变化后，正式使用前必须重新校验。
分钟 `feed` 的 READY 不代表实时 Tick 已采集或任何交易权限。实时 Tick 持久化明确返回不支持。

## 任务生命周期与存储

任务状态包括 `running`、`succeeded`、`failed`、`cancelled`、`interrupted`、`unknown`。
不估算完成百分比；详情提供真实运行日志和逐日校验结果。超时限制为六小时。
取消或异常退出不会回滚已完成的写入或删除；重试前先查看日志、覆盖与质量。

兼容一次性数据操作的元数据写入 `.local/state/api/data_jobs/operations/` 文件，不再写 ORM `ManagementJob`。既有数据库任务记录保留，不自动导入或删除。
结果位于 `.local/state/api/data_jobs/`，日志位于 `logs/api/data/`，导出位于 `data/exports/ticks/`。
数据任务与兼容管理端的检查/回测任务使用不同 action 名称，互不冒充。

API 进程启动及状态轮询时检查孤立任务。若前次 worker 仍持有继承的排他锁，状态为待确认，
不尝试按历史 PID 杀进程；锁释放后标记中断并保留结果，不自动判为成功或重试。
正常关闭服务会取消其任务并等待退出，再关闭数据库。数据库故障导致终态无法保存时，恢复后按中断处理。

数据 API 任务按产品与交易对串行，不同交易对可并行。实时采集和历史任务共享访问许可；
主动删除独占该交易对的访问许可，排斥其采集和后台读写任务。取消仅支持任务所属进程，建议单 API worker 部署。
既有手动 Pipeline CLI 不使用该 API 锁，运维时不得与管理页面同时写入或删除同一 Catalog；
删除前还须停止使用目标范围数据的回测或研究读取任务。
该版本未修改冻结管道入口的并发契约。存储不可用返回错误，不新建替代数据目录。
不提供强制重建、配置路径修改、数据库迁移或交易操作；实时采集范围以文末更新为准。

## 任务实时进度

管理员可通过同源 `WS /api/data/jobs/stream?job_id=<任务 ID>` 订阅任务快照。
沿用 HttpOnly 会话 Cookie，不把凭据放入 URL；校验 Origin，每次快照重新核验会话及管理员权限。
`job_id` 可省略，指定后附带该任务最后 32 KB 日志和结果；不接受任务指令或写入消息。
服务约每秒读取既有任务记录及活动任务日志，有变化发送
`{"type":"tasks","tasks":[...],"detail":null或任务详情}`，否则发送 `{"type":"heartbeat"}`。
`progress` 为实际日志最后一个非空行（最多 300 字符），不是完成百分比。
重连首帧发送当前快照；初次未登录/非管理员拒绝握手（401/403）；来源无效或已连接会话失效关闭 1008，存储暂不可用关闭 1013。
部署代理须支持 `/api/data/jobs/stream` 的 WebSocket Upgrade；Next.js 现有同源 rewrite 支持转发。

前端操作弹窗及右下角通知仅显示进度条和简短状态，不展示日志与结果明细，也不请求所选任务详情；公共详情接口保留兼容。
没有可信总量时使用不定进度条，成功后显示完成；详细执行信息仍保存在日志与结果文件中。
初次加载及重连不会重新提示已有历史结果。通知仅在当前行情数据页面内展示，无系统通知权限要求。
连接自动重试，最长退避 15 秒；15 秒无有效消息视为断线。
断线期间每 3 秒查询状态，各请求最多等待 10 秒，恢复连接后改为推送任务进度。
存储、实时行情和历史清单请求独立更新；任务结束会刷新清单。历史清单不扫描每条日志或逐笔校验全部数据。


## 无预设交易对

行情管理页面不再使用 `binance_sources.toml` 的研究默认交易对。
“添加交易对”读取 Binance 原生品种目录中的 USDT / USDC 永续合约，允许搜索并主动选择，不默认选中品种；
列表失败显示错误和重试，不回退 BTC/ETH/SOL。
交易对名称以引擎提供的原生合约编号为准，避免基础币种缺失或数量前缀被别名替换。读取采用已有 ExchangeService 缓存（5 分钟）。
下载计划与准备任务在 API 边界核对当前目录；历史日期是否有官方归档仍由原有下载校验决定。
查看、校验、派生和删除已有数据不依赖在线品种目录，避免退市或网络故障阻断本地管理。

管理任务将用户明确选择的品种作为本次 PipelineSettings 的 symbols，继续使用既有准备入口、
周期白名单和风险边界；冻结 TOML、准备源码、研究清单与其他 CLI 默认行为保持不变。
DATA 主列表直接使用业务数据库 `market_data_policies` 的配置，经既有 `/subscriptions?group_options=true` 读取；
不再请求 `/datasets?all_levels=true` 或旧 `/feed/status`，不遍历 Catalog 或实时成交表来发现交易对。
开始日期、保存粒度、周期和历史补齐开关取自配置；实时状态仍读取服务状态并检查有效期。
“最新数据 / 消息（UTC）”列仅显示服务状态中的实时更新时间，保留毫秒，无消息时显示“—”，不加文字前缀。
页面不再请求 `/datasets/latest`；该公共只读接口保留，通过 Nautilus 公共 `query_last_timestamp` 按已配置永续交易对定位固定 1s K 线，
不发现全部品种、不查询全部周期覆盖、不读 Tick 或实时 SQLite。结果保留 Catalog 事件时间语义（闭合边界前 1ms）。
无 Catalog 或对应 1s 数据时返回 null，不创建目录、不以其他周期或消息时间替代；存储失效返回 503，删除独占期间返回 409。
该结果只用于展示，不表示数据连续、质量通过或具备交易资格。
概览统计已配置交易对，历史补齐开关不代表已保存数据或质量通过；未配置的本地文件不自动生成管理行。
`/datasets`、`/coverage` 等公共查询及旧 CLI 保持兼容。账户配置、账户记录和任务审计记录不属于行情清空范围。


## USDC 与产品选择（2026-10-28）

USDT / USDC 永续复用既有 USD-M 原生目录、日 trades 归档、Tick 转换和 Catalog。
产品先选择，再读取交易对；`GET /markets?product=futures_um` 返回两种计价币种；
`product=options` 返回期权目录和合约属性，未知产品返回 422，不会回退到永续品种。未选择产品时前端不请求品种列表。

随后用户明确批准期权接入及冻结模型更新；实施边界见
[期权数据接入](OPTIONS_DATA_PLAN.md)。账户汇总计价逻辑不属于行情币种扩展。


## 期权产品（2026-10-28）

- `GET /markets?product=options` 返回原始合约代码、标的 underlying、到期 expiry（ms）、
  strike、right（CALL/PUT）、multiplier；目录沿用服务缓存，正式公开端点无需账户密钥。
- 所有范围请求可附 `product=options`，省略仍为 futures_um。
  `/bars`、`/ticks`、`/coverage`、`/quality`、准备/删除计划与任务使用同一产品。
  Tick 查询可用 `interval=tick`；K 线查询须指定有效周期。
- 期权 `prepare + intervals=[]` 仅表示当前获取官方近期最多 500 笔，实际事件日期可早于提交日；
  明确拒绝任意历史日期的 Tick 下载。`intervals=[1m/5m/15m]` 获取对应历史交易所 K 线。
- 期权仅支持 prepare、validate、delete。禁止将近期片段当成完整历史进行 materialize/export。
  期权 validate 的 ready 仅表示本地与捕获来源一致，不等于交易所历史完整。
- capabilities 发布 products、option_intervals、option_recent_limit=500 和 option_historical_ticks=false；
  原有 market 保留为默认永续市场，realtime_ticks 表示能力，不代表已经启动持续采集。
- 库存项携带 product 和合约属性；quality 区分 partial_recent_trades 与 exchange_klines。
  删除计划响应和指纹包含产品；文件列表精确隔离产品和合约，沿用原有明确确认流程。

来源快照、原子安装、中断恢复、精度及数据边界见 [期权接入说明](OPTIONS_DATA_PLAN.md)。

推送发布只读任务快照，不重复执行恢复扫描；恢复仍由服务启动、提交和状态接口处理，鉴权保持不变。

## 按交易对配置与分钟实时管理（2026-10-29）

管理单位为产品/交易对。“添加交易对”不要求日期；配置最小保存粒度、额外 K 线周期、
实时开关，以及可选的一次历史追加。不存在预设品种，也不在添加时自动下载全历史。

- `GET /api/data/subscriptions` 返回配置和实际运行状态。
- `POST /api/data/subscriptions` 保存配置。新请求 `base_level=1m`、`realtime_enabled=true`，
  `intervals=[]`、`history_enabled=false`。`base_level` 可为 Tick 或官方 K 线周期；
  `intervals` 为额外保存的周期，不能小于最小粒度；基础 K 线自动保存。
- K 线周期为 1s、1m、3m、5m、15m、30m、1h、2h、4h、6h、8h、12h、1d、3d、1w、1M。
  月线使用真实 UTC 自然月、周线从 UTC 周一开始，不用固定 30 天替代月线。
- `history_enabled=true` 启用持续补齐服务，不创建数据库任务，不返回 `history_job` / `history_error`。
  `history_mode=all` 从交易所最早历史开始；`start` 指定完整 UTC 日；`duration` 从已有 Catalog
  基础数据最早日（无数据则今天）向前计算天数，解析结果保存在文件中，重启不再滚动起点。
- 历史服务仅处理完整 UTC 日；Tick/秒归档推进至 UTC 两日前，旧分钟来源至昨天。
  归档未发布则保留当天位置，每 30 分钟探测一次；其他异常保留原 30 秒重试路径。
  关闭 `history_enabled` 暂停补齐，关闭 `realtime_enabled` 暂停接入；计算在任一来源开启时运行。
- 旧 `/jobs`、详情、取消和 backfill 重试保留公共兼容，只使用文件操作记录。
  同一交易对已启用历史服务时，需先暂停历史服务再执行兼容获取/校验等操作。

### 存储与来源

新显式粒度通过固定 `engine.feed.managed --policy` 子进程运行，连续数据保存在原 Feed 范围下
`data/market_data/binance_um_1m/managed/<symbol>/<base_level>/collection.sqlite`。
最小粒度变化使用独立目录，不删除、不迁移旧数据。SQLite 使用 WAL/FULL、逐笔编号去重、
闭合值冲突证据和持久缺口；未闭合 K 线仅存在临时状态。库存和预览读取该日志及已有 Catalog，
只读操作不会创建缺失目录。历史删除仍保留 Feed 数据，并要求先关闭该品种实时接入。

历史 `engine.pipeline.pair_data` 写入既有 Catalog。Tick 复用校验后的 trades 归档和冻结转换入口；
1s 复用归档读取与聚合，但不向正式 Catalog 保留额外 Tick；其他周期使用交易所原生 K 线，
避免逐日拼接出错误的周/月线。只补未存在的事件范围，不强制重建。归档是来源证据，
不属于最小粒度所约束的物化 Tick 数据集；现有文件覆盖仍不等于逐笔质量校验。

USD-M 原生适配器成交流是 aggTrade，不能用来冒充历史 raw trades。
管理端复用已有公开 HTTP 的有界读取、超时和限流退避，以固定 `trades` 端点轮询真实逐笔，
以 `klines` 获取交易所形成中及闭合 K 线。管理端逐笔成交接受编号跳号和乱序，不检查编号
连续性，不由跳号触发补洞或降级；旧编号缺口记录保留但不再参与判断。
不调用要求 API Key 的 historicalTrades，不用 aggTrade 编号替代逐笔成交。
高频品种的近期窗口可能溢出，本实现不承诺无需归档即可实时恢复任意逐笔缺口。

新管理采集状态仅描述该日志，不是原分钟 Feed 的策略就绪授权；所有更新
`allow_new_risk=false`。不注册执行客户端，不读取账户密钥，不启动策略交易。
服务器校时失败、内部分页缺口、行情过期或闭合值冲突均不能发布健康状态。

## 2026-10-29 按交易对协调数据任务

数据任务不再使用项目级 `data.lock` 串行。锁位于

## 固定 UTC 历史开始日期（2026-10-30）

启用 USD-M 历史补齐并保存配置时，三种选择仅用于确定开始日期：

- 全部历史：查询交易所最早可用分钟，将其对齐到当日 UTC 00:00；查询失败不覆盖原配置。
- 指定起点：先转换到 UTC，再取该 UTC 日期的 00:00，忽略时分秒。
- 追加 N 天：从已配置开始日期向前推 N 个 UTC 日；尚未配置起点时，从本地最早基础粒度
  数据的开盘 UTC 日期向前推，无数据时以今天 UTC 00:00 为基准。

数据库复用原参数字段，保存 `history_mode=start`、明确的 `history_start`，
`history_days` 恢复默认占位值，不再参与服务运行。前端重新打开配置时展示已保存起点，
重启、恢复或原样保存不再次向前追加。停止历史补齐时保留该日期。
处理检查点仍在 `history/checkpoint.json`，与期望覆盖起点分开；来源选择、计算通知、
补缺及冲突保护不变。旧数据库参数不批量改写，下次启用历史并保存时统一解析；
已有 CLI 和旧模式解析保留公共兼容。不迁移数据库、不清理行情或重写冻结来源。


## 分层历史核验与官方周期（2026-10-30）

管理端 USD-M K 线周期固定为 `/fapi/v1/klines` 的
`1m、3m、5m、15m、30m、1h、2h、4h、6h、8h、12h、1d、3d、1w、1M`。
该接口实测 `interval=1s` 返回 `-1120 Invalid interval`，不采用其他端点公共枚举中的秒线。
页面移除周期勾选，只选择全部 K 线或 Tick 加全部 K 线。原 `intervals` 字段保留请求兼容，
2026-11-08 起，显式 USD-M 配置返回本地 1s 加官方 15 个周期；旧显式 `1s` 基础配置读入时仍转为 `1m`，
旧 `auto` 配置仍可恢复原分钟 Feed，下次保存时转为全部周期的显式分钟配置。
期权仍限原接入能力，不将 USD-M 周期直接套用到期权。

参考用户部署包的 gap-repair 算法，历史服务按完整 UTC 日执行
`1d → 4h → 1h → 15m → 5m → 1m` 的差异定位，直接比较已保存历史 K 线的 OHLCV，
旧分钟目录缺少高周期时可从已保存分钟线汇总，不扫描 Tick。保存的 Bar 不含成交笔数，
本核验范围为 K 线 OHLCV，不替代独立逐笔核验。相等分支不请求更小周期；仅缺失数据被追加，
已有不同来源值或同编号不同成交保留原始证据。来源空页、缺口、精度异常及父子对照矛盾
不能声明通过。来源不足的 UTC 首日按交易所最早实际时间处理，不制造前置成交。

逐日核验结果写在原 managed 目录的 `history/audits/YYYY-MM-DD.json`，
检查点记录游标及未解决日期；完成日期记录 `verified=true`、配置摘要与核验版本，
同配置下不再自动复扫，旧游标重放也直接跳过。归档修复后先完成既有派生通知，再复核保存结果，
成功才标记完成；等待计算、来源冲突和失败日期不标记。旧版本与其他配置的证据不能当作
当前完成标记；只有未解决日期保留五分钟重试。未解决差异使历史状态保持 DEGRADED；
普通下载/写入失败重试当前日期。来源变化沿原文件通知交给计算服务，
全部周期按各自 UTC 边界生成，未闭合或不完整的窗口不冒充完整。
该证据不替代逐笔归档一致性校验；已有闭合派生值冲突仍保留待办供排查。

归档调度采用 UTC 发布窗口：UTC 日期 D 仅尝试 D-2 及更早的 Tick/秒来源。
Tick/秒来源的未完成日期先确认归档可用，再比较保存的 K 线；本地有效 ZIP/CHECKSUM 直接复用。远端 CHECKSUM 或 ZIP
未发布（404）时记录 `archive_wait` 至原 `history/checkpoint.json`，30 分钟后再探测。
等待期间不重复执行整天差异扫描，也不推进或伪造覆盖；重启不绕过已记录的等待。
仅发现 K 线差异后才下载、转换归档并在更正环节去重、核对同编号冲突及补缺。
近期 1,000 条 REST 成交保留为每次连接后的一次有限尝试，失败不每隔 30 秒重复补录，
下次重新连接才再尝试；失败状态保留，实时 WebSocket 继续接收，历史缺口由归档核验。

当前实时路径为原始成交聚合 1s，再直接生成分钟至月线；1s 长期保存在原采集库。
同批秒变化按目标窗口合并重算，高周期顺序读取秒线，不把整周/月秒线展开为内存列表。
启动不完整窗口、原源覆盖验证、闭合水位、迟到重算、去重、恢复及禁止新增风险规则保留。
旧秒线数据不删除，已有兼容入口及遗留待办的恢复能力保留；不迁移行情到 ClickHouse，
不新增服务或数据库迁移，不自动下载或改写正式运行数据。


3d 分组已与实际 Binance K 线开盘时间核对，使用 Unix 纪元加一天的 UTC 锚点；
周线继续使用 UTC 周一，月线使用自然月。未重写已有 3d 文件；旧文件若与修正后的闭合
结果冲突，沿现有冲突保护保留并报告。


## 配置驱动的开始日期与删除（2026-10-30）

前端只在交易对配置中编辑开始日期，不再单独追加历史数据；追加模式及天数仅保留旧
HTTP / CLI 输入兼容。开始日期早于旧配置时，保存后由原历史进程重置其扫描范围并自动
核验补缺，仍遵守历史自动补齐开关；实时采集参数未变时继续运行。

- `POST /subscriptions/plan`（管理员）：提交原 DataPolicy，返回规范化 `policy`、
  `requires_confirmation` 及可选 `deletion`。调晚时先暂停当前服务并持独占读写许可生成快照。
- `POST /subscriptions`：兼容原参数。需要裁剪时另外提交计划的 `deletion_snapshot` 和
  `confirmation=DELETE 交易对`；返回含 `job` 的配置操作结果。普通保存仍返回原订阅结构。
- 配置和实际文件均绑定确认快照，数据或参数变化返回 409，必须重新预览。其他交易对可继续运行。

裁剪范围是新开始日期之前的 Tick、全部周期 K 线、相关特征缓存和完整日原始归档及校验文件。
跨界 Parquet 保留范围内记录并更新文件区间命名；周、月等 K 线若包含旧日期来源则移除整根。
托管实时日志同样按记录裁剪，历史待办及检查点失效，防止旧通知重建已删数据。
完整月归档跨界时保留官方原文件，无法确认时间的来源或异常证据保留，均在预览中明确说明。

`trim` 复用原数据任务进程、互斥许可、日志、取消、六小时超时和文件状态记录，不新增服务。
逐文件复核身份、临时写入和原子替换；全任务不是跨文件事务，中断可能只完成部分删除。
只有成功后才保存新开始日期并恢复用户选择的服务；失败、取消或进程所有者丢失时保持旧日期
与暂停状态，需重新检查并确认。确认字段不写入 `market_data_policies`；账户、研究报告、
合约定义及其他交易对不受影响。本轮仅实现与离线测试，没有对正式运行数据执行裁剪。


## 期权全选与新合约自动纳入（2026-11-07）

旧全选范围继续兼容；`POST /api/data/subscriptions/plan` 与
`POST /api/data/subscriptions` 接受 `product=options, symbol=ALL` 的全选配置，
支持实时采集与历史补齐开关。ALL 仅为配置范围，行情与兼容获取请求仍要求具体合约；
新增标的级配置、展示和删除见下文“期权按标的交易对管理”。
复用 `market_data_policies` 和现有每 15 秒恢复流程、5 分钟缓存目录，不迁移数据库。
新合约自动继承保存方式与开关并启动所选服务，自动发现不覆盖已有单合约配置。
显式保存全选配置时统一应用到已纳入合约；有合约正在删除则拒绝保存，避免重新启用采集。
目录失败保留原配置并发布同步错误，下轮重试；到期合约及数据不删除，实时订阅到期停止。

采集使用 `engine.feed.managed --options-config` 的一个共享进程，复用期权 connector 的公开传输与
原生行情解析，保存闭合 1m/5m/15m K 线，可额外保存实时 Tick。源证据经原 Feed history 桥交由 Pipeline
保存到既有 raw/options 和 Catalog，不新增存储层或交易能力。期权不另起本地派生进程。
有界队列施加背压，订阅确认异常、数值或来源冲突显式降级。重启重放尚未物化的已保存来源，
重新连接后补取断线以来官方可用的闭合 K 线；近期成交仅补最多 500 笔，
断线和重启证据保留在 managed 文件，始终不声明历史 Tick 完整，不从 K 线反推成交。

历史沿原 `engine.pipeline.pair_data --service` 进程转入期权管道，按完整 UTC 日获取官方 K 线，
检查点在 managed/<symbol>/<base>/history。默认从官方最早可获取记录日开始，
指定起点早于来源时以实际可用日为准。空来源、解析或写入失败保留当前日重试，
不以空响应证明历史完整。到期日仅保存到期边界内闭合记录；交易所不再提供的记录不能补造。
期权起点只控制补齐范围，调晚不删除已有数据。历史开关用于 K 线，选择 Tick 也不会请求虚构的完整历史逐笔。

同合约实时、历史与手动获取使用原文件存储内的写锁，来源快照先写入再原子安装原生文件。
托管路径可合并原文件内部的缺失记录和迟到成交，已有不同值仍拒绝覆盖。
删除交易对预览包括期权来源、写锁状态及 managed 文件，原确认/指纹/停止采集保护保持。
单合约官方数据获取、配置编辑和确认删除保留；全选开启时删除仍在目录中的合约后，
后续同步会重新加入并按开关采集或补齐。要停止自动恢复，先关闭全选范围内的相关开关。

用户随后明确授权共享连接与批量托管，已移除临时 32 合约限制。API 只管理一个期权采集
进程和一个期权历史进程，不为每个合约创建进程或向子进程传递整份合约的文件描述符。
授权参数仍来自业务数据库；`.local/state/api/data_jobs/options-runtime.json` 是可重新生成的
运行快照。两个进程每秒读取快照，内容损坏或读取失败保留现有工作，不将异常当作空配置。
独立命令 `engine.feed.managed --policy` 和 `engine.pipeline.pair_data --service --request` 保留兼容。

公开 WebSocket 每组最多 64 个合约，共享一条 market K 线连接和一条 public Tick/盘口
连接。2026-11-08 按用户要求，管理端所有启用实时的期权均订阅 Tick 和前 10 档盘口（100ms），
不受最小 K 线粒度影响。Tick 写原 Catalog；盘口精确价量、更新编号、交易所时间与接收时间
按批次持久化到 `raw/options/<合约>/depth/<UTC日>/` 的 SHA256 JSON 原始来源，不只保留最新值。
盘口断线缺口不能由历史 K 线补齐，当前 API 不提供盘口历史预览。
新增、停用和到期使用订阅/退订及确认，不重连同组其他合约；模拟 1,514 个合约共 48 条连接。
每个合约仍持有独立 writer/access 锁和检查点，
单合约删除等待该合约采集与历史工作释放读写保护，不终止其余合约；超时保留暂停并返回 409。
源队列与传输队列有界并施加背压；暂停与到期先停止投递，再保存已接受的队列尾部，
访问锁在写入完成后才释放。断线与重建保留缺口证据。历史服务最多同时执行两个来源
获取/物化工作，实时断线补取也最多两个；补取排队时仍可保存收到的实时证据，状态不冒充就绪。
公开 REST 沿原白名单与限流退避；目录定义共享缓存，新上市合约缺定义时主动刷新，
没有官方或本地定义时显示等待，不创建推测的合约单位。即使尚无行情，也先保存公开目录的真实
合约定义，以便到期退出目录后恢复；这不会产生 Tick/K 线或虚构数据覆盖。运行服务不配置账户或执行客户端。

验证使用临时数据与本机模拟交易所，包含 1,514 合约进程/连接规模、动态订阅、单合约停用、
删除锁释放、损坏运行快照、迟到/重复/冲突数据、来源写入中断及历史检查点续跑。
另完成两个真实公开合约的共享订阅确认，只读且不保存正式行情；未对正式全量长期流量或
完整历史回溯做线上压测，不将模拟结果视作所有历史数据已补齐。


## 期权按标的交易对管理（2026-11-07）

按用户要求，页面添加及主列表改按 BTCUSDT、ETHUSDT 等标的交易对管理，
不单列到期日、行权价或方向。库存范围汇总保留未校验标记；某个合约过期、故障或
状态过期不会被其他合约的新鲜状态掩盖。服务监控也按标的汇总，后台仍为两个共享进程。

原配置表中的标的级 DataPolicy 统一控制已有及后续新合约；合约级参数、来源及存储
保留具体合约身份，不能把不同期权价格合成一份行情。原 ALL 和单合约接口继续兼容；
前端查询 subscriptions 时增加 `group_options=true`，返回标的级配置和服务观察。

标的级 pairs/delete/plan 与 pairs/delete 先暂停其下全部合约，再检查预览指纹；
worker 按合约取得 job/access 排他锁并核对文件身份。中断或冲突可产生部分删除，
失败保留暂停配置，须重新预览。成功后移除该标的配置及旧 ALL 自动发现范围，
其他标的的显式配置不变，避免已删除标的被重新纳入。合约定义、账户、交易记录、
研究报告及其他产品数据保留。单合约删除入口继续支持。

旧的逐合约“获取官方数据”弹窗随列表合并移除；固定 HTTP / CLI 获取、校验和
删除入口仍保留。旧期权历史仅在本次用户授权的部署清理中通过既有删除函数处理，
不会随普通启动自动删除。无新增表、服务、存储层或交易能力。
