# Demo：现货做多 + 永续做空（资金费率 Carry）

**状态：可校验的研究示例；不可通过当前 Engine 执行/回测跨市场订单。**
此示例不是低风险或保证盈利策略。

## 交易逻辑

- 对同一基础资产，目标持有 `+Q` 现货及 `−Q` USD-M 永续，方向相反且按**基础资产数量**对冲，绝不能把名义金额相等误当数量相等。
- 仅当**实际且未过期**的资金费率达到 `min_funding_rate` 且永续相对现货基差未超过 `max_basis_bps` 时，形成持仓目标；费率不足或基差过大时目标归零。
- 必须同时提供现货及永续行情、费率、真实仓位及时间戳。过期、缺失、未来时间、仓位方向异常或两腿净敞口超过 `max_leg_drift` 时停止新增风险；不能靠单腿下单“修复”。
- `expected_gross_funding` 是下一次结算的毛资金费**估算**，不是实际到账，也不含基差变化、成交手续费、滑点、现货借贷/库存机会成本及永续保证金风险。正费率代表空头收款，不代表套利净收益一定为正。

`logic.snapshot_plan(snapshot, params)` 提供无网络/无账户操作的确定性多腿目标。行情和费率必须从交易所及账户真实证据输入，不可由现货 K 线推导伪造。

## Engine 依赖

当前 Engine 的 `PortfolioCoordinator`、`run_issued_history` 都是单一品种/单一账户执行路径，无法区分相同交易对的现货与永续、协调不同资金账户和在某一腿失败时及时补偿。因此 `DemoFundingCarry.on_start` 明确拒绝缺少 `subscribe_market_bundle` 与 `publish_basket` 的运行环境，**不提交任何单腿订单**。

正式可运行前需要：跨产品 InstrumentId 与行情对齐、FundingRateUpdate 的真实结算现金流、跨市场独立资金/保证金、原子组合意图及部分成交恢复、交易成本与持仓风险约束、历史模拟/真实账户回归。不能把这个研究包直接授权为生产策略。

参数：`allocation`、`risk_limit` 为基础资产数量上限；`min_funding_rate` 是每次结算的比例而非年化收益率；`max_basis_bps` 为基点；`max_age_seconds` 限制所有证据新鲜度。

上传策略包时将本目录内容打成 ZIP（元数据文件位于压缩包根目录）。上传与下发不会自动开启任何真实交易。
