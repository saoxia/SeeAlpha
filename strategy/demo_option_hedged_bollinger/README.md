# Demo：双向期权保护 + 布林带均值回归

**状态：已实现离线信号/多腿目标计算；当前 Engine 不具备跨永续与期权的多腿实盘或端到端回测接线。**

## 思路

1. 在收盘 K 线上使用 `period` 根收盘价计算中轨、标准差以及 `deviation` 倍上下轨。空仓时低于下轨计划做多永续，高于上轨计划做空永续；持多时回到中轨以上退出，持空时回到中轨以下退出。未收盘、倒序、重复 K 线直接拒绝。
2. 入场需**同时买入看跌和看涨期权**，分别保护永续多头的下跌尾部与空头的上涨尾部。给出的交易意图包括 `+put`、`+call`、`+perp/-perp` 三腿；退出归零三腿。
3. 方向仓位 `Q = min(allocation, risk_limit)`，并要求两种期权各自 `option_contracts * multiplier >= Q`，保证保护腿的基础资产覆盖数量不小于永续净敞口。保护腿**必须先真实成交并核实**，再允许增加永续方向风险；不能独立下三张单。
4. 必须选择真实的同标的、同到期日、行权价分居当前价格两侧的 Binance 看涨/看跌期权；报价和合约信息必须最新，距离到期大于 `min_dte_seconds`，卖盘数量足够，权利金估算不超过 `max_total_premium`。不自动选期权、不自动展期。
5. 如果价格跌破看跌行权价或升破看涨行权价，给出三腿归零目标。即使保持双向长权利金策略，**行权价以前仍可能损失很大**，权利金损耗、Delta/Gamma、隐波变动、流动性以及永续爆仓均不能视作已经被完全消除。

`logic.BollingerModel.propose(snapshot, params)` 在不接触交易所的条件下输出可验证的策略目标；只有目标被组合执行器接受后才调用 `commit(plan)`。风险和交易所限额应由 Engine 的原生风控与专用多腿协调器控制。缺少有效报价时不增加新风险，不能凭空构造期权价格。

## 当前运行边界

- `put_symbol`、`call_symbol` 在模板中留空：必须由用户从真实合约目录选择，避免默认示例在某天自动过期。上传策略包允许留空，但运行前必须填写。
- `DemoOptionHedgedBollinger.on_start` 在缺少跨市场 `subscribe_market_bundle`、`publish_basket` 能力时直接拒绝，故**当前不能通过普通单品种策略回测或实盘下单使用**。
- 执行引擎接线前，需要具备：历史期权买卖报价/真实合约目录、时序同步、合约乘数/交割、期权/永续共账户风险与真实成本、先对冲后暴露及部分成交/撤单恢复、期权到期停止与清算、可审计成交证据等。策略没有做自动展期，也没有使用由 K 线虚构的 Greeks。

ZIP 根目录放 `strategy.py`、`logic.py`、`seealpha-package.json`、本说明文件，便于策略商店登记。演示策略不承诺盈利。
