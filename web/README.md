# SeeAlpha 独立前端

账户记录的类型筛选新增“资金变动”，实时操作面板也显示已经保存的资金费、手续费、
已实现盈亏、划转及其他合约收支。资金行展示原精度有符号金额、币种和流水号，不显示成交价格。
应用“资金变动”筛选后更新记录仅同步资金；其余筛选仍更新订单及资金两类记录。
未指定开始时间时，订单沿用最近 24 小时，资金从已有检查点续跑、首次检查最近 87 天。
资产曲线使用启用后保存的账户与估值证据；账户快照历史倒推未接入，不能把资金流水列表视为完整账户历史。

`app/`、`public/` 和根目录前端配置组成独立 Next.js / React 前端。
用户鉴权、Binance 账户、操作记录和 OLAP / ClickHouse 监控通过 [`../api/`](../api/README.md) 提供；预估资产 K 线读取持久化的真实估值，缺口保留空白。

LIVE 顶部“刷新资产”立即刷新所选账户或总览的余额及资产价格。账户面板显示分币种余额、
USDT 估值及价格时间；低于 5 USDT 的资产折叠展示，仍计入估值，非 USDT 小额价格最多
缓存一小时，其余价格一分钟，余额变化会重新取价。旧价仅作参考，缺价不当作零；
交易所汇总与价格估算明确区分，估算不用于保证金或交易风控。详见
[刷新资产说明](../docs/BINANCE_NATIVE_API.md#刷新资产与小额资产2026-11-07)。

## 前端启动

需要 Node.js >= 22.13.0 和 npm。先按 [引擎](../engine/README.md) 与 [API](../api/README.md) 说明启动常驻引擎和 API，再运行：

```bash
cd web
npm ci
cp .env.example .env.local
npm run dev
```

`npm run dev` 使用 webpack，并且只监听 `127.0.0.1:3000`。本机打开 <http://127.0.0.1:3000>。
修改页面后自动刷新。不要把开发服务器绑定到 `0.0.0.0` 或局域网地址。

局域网访问使用生产构建。先停止开发服务，在项目根目录启动引擎和 API。`LAN_IP` 是这台机器当前的局域网地址，只放在启动环境里，不写入仓库：

```bash
# export LAN_IP=当前局域网地址
COOKIE_SECURE=false \
ALLOWED_HOSTS="localhost,127.0.0.1,${LAN_IP}" \
ALLOWED_ORIGINS="http://127.0.0.1:3000,http://localhost:3000,http://${LAN_IP}:3000" \
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

再在 `web/` 构建并以生产模式监听局域网：

```bash
cd web
npm run build
npm run start:lan
```

同一局域网设备访问 `http://${LAN_IP}:3000`，并允许防火墙的 3000 端口入站。
地址变化时只更新 `LAN_IP`。本机私有文件 `.local/config/api/lan.env` 可以保存这些变量，
启动 API 前运行 `source .local/config/api/lan.env`；该文件不提交。
`next dev` 默认不放行额外来源。只有确需在开发模式从其它主机访问时，才在 `.env.local`
把 `SEEALPHA_ALLOWED_DEV_ORIGINS` 设为该主机名（不含协议、端口或通配符）。日常局域网访问不使用这条路径。
本机生产模式执行 `npm run start`，只监听 `127.0.0.1:3000`。
API 仍仅监听本机，通过前端同源代理访问；`COOKIE_SECURE=false` 仅用于可信局域网的 HTTP 测试，
正式部署继续使用 HTTPS 和 Secure Cookie。
`output: "standalone"` 仍然保留。Next.js 16.4 执行 `next start` 时会提示独立产物改用
`node .next/standalone/server.js`；仓库脚本继续使用 `next start`，页面和 `/api` 代理由该进程提供。
生产构建会把 `SEEALPHA_API_URL` 写入转发规则，改地址后需要重新执行 `npm run build`。

浏览器只通过同源 `/api` 交互，前端不直接访问项目 Python 模块、数据库或本地业务文件。
服务端代理配置：

- `SEEALPHA_API_URL`：API 地址，默认 `http://127.0.0.1:8000`，承接鉴权、用户与租户、健康、账户配置、品种列表、余额、账户/仓位、操作记录、研究任务及 OLAP / ClickHouse 监控接口。

前端请求转发到项目 API；生产构建同样需要设置目标地址，或由正式反向代理接管 `/api`。
正式部署采用同域 HTTPS，API 使用 Secure 会话 Cookie。
页面没有使用 `next/image`。配置关闭图片优化，并且不设置远程图片来源，`/_next/image` 不再做图片抓取。

`npm run lint` 检查当前前端，`npm run test:frontend` 运行已有前端测试，
`npm run build` 构建生产版本，`npm run start` 在本机启动该构建。

图表价格的小数位，默认沿用合约价格步长，未取得步长时按行情价格推断。只改变显示，
下单输入、确认价格与请求保留原始精度。资金费率显示五位小数百分比及距下一结算的倒计时，
每秒更新；未取得结算时间时显示空值。结算间隔由公开 `fundingInfo` 读取，成功响应中无调整项时使用官方默认 8 小时，失败不标注间隔。

主导航 **TRADE** 位于 LIVE 与 DATA 之间，按 Binance USD-M 交易页布局提供合约搜索、
账户选择、带自选/筛选/行情排序的交易对弹出列表、TradingView K 线及可编辑周期/价格来源/颜色/线宽的多组技术指标、图表价格线显示设置、全屏交易、盘口、最新成交、限价/市价下单、持仓及委托撤单。
实盘/测试网明确区分；仅管理员可操作，提交前确认，未知结果先查询，不自动重发。
下单区展示当前合约的实际杠杆倍数，缺失或快照过期时显示“—”；原来的设置说明与持仓模式说明已移除。
账户杠杆、保证金和持仓模式沿用交易所设置，页面自动匹配开仓/平仓方向；完整功能范围、限制和恢复说明见
[手动交易](../docs/MANUAL_TRADING.md)。

## 研究与任务

主导航 **RESEARCH** 提供项目检查、已有报告和任务日志。页面约每十秒读取已发布状态，选中任务的日志约每两秒更新。
过期检查不能视为当前正常。接口为 `/api/management`，登录沿用 API 会话；
启动任务和取消任务需要管理员，只读用户可以查看。

- **总览**：检查结果、任务是否空闲、报告数量和最近任务。
- **项目检查**：快速检查运行 Ruff 与冻结来源测试；完整检查运行 Ruff 和全量 pytest。
- **策略回测**：管理任务动作列表已移除废弃的本地研究回测入口。历史回测改在开发租户通过 Engine HTTP 运行已下发的策略包；旧报告和任务历史仍可只读查看。
- **报告**：打开已有交互报告和统计 JSON。链接只接受已发布的 `/artifacts/` 路径。
- **任务记录**：状态、输出日志、取消和打开本次报告。

已有报告仍可从 `data/reports/backtest/<策略>/<run_id>/` 打开，组合位于其 `portfolio/` 子目录。
研究目录不再生成新的策略回测报告。API 同时只运行一个检查任务。检查最多 30 分钟，超时会终止任务。
取消会停止该任务的子进程组；已产生的部分文件可能保留，不能视为完成的报告。
持锁进程启动时，未完成记录标记为中断，不会自动恢复，也不会向旧进程发信号。

不提供任意命令、文件浏览、密钥设置或实盘下单。策略源码和冻结参数不在此页面修改。

任务记录在启用 ORM 时写入业务数据库表 `management_jobs`，报告索引写入 `backtest_reports`。
未启用 ORM 的测试或临时运行仍使用 `.local/state/web/jobs/` JSON。日志仍在 `logs/web/`。
API 启动时尝试持有 `.local/run/web/server.lock`。拿到锁的进程执行这些任务；
未拿到锁的进程仍提供查询，启动和取消返回 409，因此多份 API 不能同时执行这些任务。
若 `data/web_console/` 仍有旧任务文件，由持锁进程迁入上述目录；同名内容冲突则拒绝覆盖。
旧管理端的独立口令文件若被一并迁走，只作为私有文件保留，不再用于登录。

```bash
.venv/bin/python -m pytest tests/web tests/api/management_test.py -q
```

## 行情数据管理

主导航 **DATA** 统一提供“行情数据”“账户记录”和“数据监控”三个标签页。
原 DATA OPS 的 ClickHouse 数据水位监控位于“数据监控”，保留刷新、添加/移除监控
及监控设置；连接配置仍在 SETTINGS 的 OLAP 数据库连接中。

「数据管理 → 行情数据」按产品/交易对展示配置的数据开始日期、实时状态和历史补齐开关，支持筛选。
“添加交易对”与“查看详情”共用配置表单，可设置保存方式、UTC 数据开始日期、自动补齐和
实时更新。采集、补齐与 K 线计算由已有后台服务按配置处理，前端不展示具体任务运行信息。
只读用户可查看配置，写操作需要管理员及可用的数据存储。

开始日期调早后由历史服务按配置自动补齐；调晚仍须预览裁剪范围并输入 `DELETE 品种`，
确认后才删除此前行情、缓存及原始归档。独立“删除历史数据”入口已移除，统一在交易对配置中
维护开始日期；删除交易对及期权已有官方数据获取入口保留；期权已支持持续采集及官方 K 线自动补齐，历史 Tick 保留来源限制。
手动“校验底层成交 / 校验本地来源”的菜单、弹窗和提交逻辑已移除；后台必要的数据校验
及已有 HTTP / CLI 校验兼容入口保留，不削弱下载、入库、自动补齐和数据一致性检查。
页面自动刷新数据状态，提交和处理结果保留简短提示；超时或断网不自动重发，状态待确认
不能当作成功。后台互斥、删除快照、异常恢复与公共兼容接口保持不变。
文件覆盖不代表连续或质量通过，行情状态不授予策略交易资格。
接口与恢复语义见 [数据管理 API](../docs/DATA_MANAGEMENT_API.md)。

## 新增与编辑 Binance 账户

账户表单只需填写账户名称、环境、API Key 与 Secret，编辑时可留空保留已有凭据；
不再选择交易对、不加载品种列表，也不显示历史已选交易对数量。
账户余额与仓位通过原生查询自动读取；行情采集和策略品种仍另行配置。
后端历史字段及公开品种查询接口的兼容说明见 [Binance 原生查询说明](../docs/BINANCE_NATIVE_API.md)。

行情数据页自动刷新配置和状态，不请求全量数据覆盖或旧分钟 Feed 状态。
“最新数据 / 消息（UTC）”列仅显示实时更新时间，保留毫秒，不加文字前缀，无消息时显示“—”。
页面不再轮询最新 Catalog 1s K 线时间；原只读查询接口保留兼容。查看详情与添加交易对共用同一份配置表单，
可调整保存方式、数据开始日期、自动补齐和实时更新。只读用户可查看配置。
页面不再提供任务进度、任务通知、服务积压、后台阶段或最新 K 线明细；
保存、提交和处理结果保留简短提示，失败或状态待确认不会显示为成功。
后台任务状态仍用于交易对互斥，服务端日志、公共任务接口及恢复机制继续保留。
开始日期调晚及删除交易对仍须预览并确认，不因简化展示而跳过删除保护。

行情管理没有默认交易对。主列表直接读取业务数据库中的交易对配置，不再遍历 Catalog 或实时成交表；
“添加交易对”从 Binance 当前 USDT / USDC 永续品种中搜索选择，加载失败可重试。
这不依赖账户配置，也不会自动下载整份品种目录。

期权添加时选择 BTCUSDT、ETHUSDT 等标的交易对，自动纳入其全部到期日、方向与行权价，无需逐一选择合约。
标的范围持久化在原配置表，旧 ALL 范围继续兼容；API 沿现有 15 秒配置恢复循环同步目录（复用 5 分钟目录缓存），
新上市合约自动加入配置并启动所选服务，已到期合约及数据保留；自动发现不覆盖已有配置。
页面按标的交易对汇总配置、数据与服务状态，不再展示单个到期日或行权价的合约行。
保存配置统一应用到该标的已有合约，新合约自动沿用；旧单合约 HTTP / CLI 入口保留兼容。目录失败保留配置并提示，后续重试。
新增期权默认开启实时与历史补齐；保存官方闭合 1m/5m/15m K 线，可额外保存实时 Tick。
重启恢复订阅，断线补取官方可用 K 线及最多 500 笔近期成交，Tick 缺口仍明确保留。
历史按完整 UTC 日及文件检查点补齐，起点仅控制期权补齐范围，不删除已有数据。
近期 Tick 是接口实际返回的最多 500 笔，按真实日期展示，非完整历史或持续采集。
历史 K 线直接来自交易所，不生成虚构 Tick；库存、任务与筛选均区分产品，
本地来源校验不冒充交易所历史完整性。添加时切换产品会清空上一产品的选择和计划。

行情清单按产品/交易对归组，点击名称或“查看详情”打开与添加交易对相同的配置表单。
实时范围及未实现项以 [数据管理说明](../docs/DATA_MANAGEMENT_API.md#按交易对配置与分钟实时管理2026-10-29) 为准。

行情入口为“添加交易对”，添加时不选日期，默认 1m 最小保存粒度并开启实时更新。
配置可多选额外 K 线周期，不能选择小于最小粒度的周期；历史追加默认关闭，开启后提供
“最早可用历史 / 指定 UTC 起点 / 向前追加天数”三种方式。仅指定起点时显示日期输入。
追加天数以已有 Catalog 基础数据最早日为锚点，无数据以今天为锚点；解析后写文件固定。
历史启停由配置控制，不再提交任务；服务故障从文件检查点续跑。

新实时采集按选定粒度保存，关闭实时在数据盘不可写时仍可操作。Tick 近期来源不完整时保留缺口，不能视为完整历史；期权连续采集和官方 K 线自动追加
按配置启停，已有近期成交及历史 K 线入口保留。更改配置不删除历史数据，所有数据状态均不授予交易资格。


### 删除交易对及全部行情数据

行情数据管理每行的操作菜单新增“删除交易对”。管理员先点击“停止采集并预览删除”，
服务会关闭该交易对的实时与历史追加配置，列出全部日期、全部周期的 Catalog Tick / K 线、
来源归档（含未完成文件）、转换 / 失败记录、指标缓存和该交易对 managed 目录内的实时数据。
预览后取消不会自动恢复采集。输入 `DELETE 交易对` 后创建固定 `delete_pair` 数据任务，
沿用任务互斥、文件指纹核对、逐文件身份检查、取消和超时机制。没有行情文件的配置也可删除。

只有文件删除成功后才移除配置；失败或中断保留已关闭的配置，可能已有部分文件被删除，
须重新预览后处理。删除期间拒绝该交易对配置变更；最后一个配置删除后也推送空订阅列表。
保留合约定义、账户、操作记录、任务审计、研究报告及已导出的独立文件；不操作独立运行的
旧版共享分钟 Feed 存储。执行前须停止手动采集、Pipeline 和相关回测。

接口为管理员 `POST /api/data/pairs/delete/plan`（symbol、product，停止采集并预览）和
`POST /api/data/pairs/delete`（另需 deletion_snapshot、confirmation，返回 202 任务）。
页面不再提供独立“删除历史数据”操作；后台日期范围删除接口保留兼容，默认保留归档。

行情管理主列表的交易对说明只显示最低数据粒度，数据开始日期列显示配置中的 UTC 起点，未设置时显示“未设置”；详情用于查看和调整交易对配置。


## 2026-10-29 实时优先与数据变化触发的 K 线

本轮按用户要求先完善实时接入，历史归档补齐与回溯留待下一步。沿用独立的
`engine.feed.managed --policy` 实时进程和 `engine.pipeline.pair_data` 历史任务进程，不启动新的后台服务。
实时进程接收原始 `@trade` 事件，逐笔去重落盘后登记待计算桶；按照 Tick → 1s → 所有更高周期，
直接从秒线覆盖重算受影响范围，成功后确认待办。重复事件不重复计量，等价的派生结果不增加版本；
重启恢复未完成计算，连接交接失败不丢弃继续收到的实时成交。

永续近期 1,000 条补录每次连接仅尝试一次（请求内部仍有限次重试），失败保留提示，
不按定时器重复补录。Tick/秒历史仅处理 UTC 两日前及更早日期；归档延迟发布时每
30 分钟检查一次，等待进度保存在原检查点，期间不重复进行整天核验。

历史自动核验直接比较已保存 K 线；一致日期，以及归档修复、计算完成后复核通过的日期，
记录完成标记后不再自动扫描。仍有冲突或等待计算的日期保持未完成；调整配置后按新参数核验。

非 Tick 配置仅使用有界原始成交工作集；1s 长期保留并展示，旧内部缓存仍按原标记清理。
未闭合更新与闭合数据分开，缺口和不完整窗口不假装完整；所有管理数据仍禁止新增交易风险。
保留已有本地 Catalog 成交的只读补缺桥，复用相同聚合路径。历史 ZIP 下载、归档未就绪
的任务处理逻辑本轮未修改，不会因本轮部署自动重试失败的历史任务。


## 2026-10-29 按交易对协调数据任务

数据任务不再使用项目级 `data.lock` 串行。锁位于
`.local/run/api/data/<product>/<symbol>.job.lock` 与同目录的 `<symbol>.access.lock`：

- 历史准备、追加、校验、生成、导出与删除任务持有该交易对的独占 job 锁。
- 历史任务与实时采集持有共享 access 许可，允许同交易对实时与历史并行。
- 主动删除持有独占 access 许可；“删除交易对”先停止该交易对采集，再独占预览和删除。
- worker 继承其锁文件描述符，API 退出后仍保留保护，直到子进程停止。
- 任务恢复逐交易对核实锁，并重新读取终态，不影响其他交易对正在运行的任务。

前端仅阻止同产品 / 同交易对的冲突任务，运行状态未知的任务也按该范围保护。
保存历史追加参数、但实时采集参数未变化时，不重启已有采集进程。
同一交易对的非重叠日期任务目前也串行：日归档、跨日 K 线和后续指标缓存的真实文件范围
可能重叠，尚不按页面日期拆锁。手动 Pipeline / 回测仍沿用原并发约定，操作目标数据前需自行协调。

本轮不改变存储职责、HTTP 契约或替换算法，不增加后台服务、消息队列和数据库迁移。
升级前须完成或停止旧版本的数据任务，不能让仅持旧全局锁的 worker 与新版混跑。


数据页首次状态与清单请求仅随页面挂载启动，不因权限返回、连接切换或弹窗状态变化
重复取消重发。WebSocket 不可用时，操作状态随常规轮询更新；账户列表按账户记录页需要加载。
读取超时显示“请求超时，请稍后重试”，不会把响应体超时当作空结果成功。
行情状态轮询失败时合并相同错误，并列出受影响的存储与任务状态、交易对配置或数据清单；
保留上次读取的数据及过期警告，相关请求恢复成功后清除对应警告，失败期间继续禁止写操作。
写入请求的 TimeoutError 类型保持不变，仍按既有流程核实任务状态，不自动重复提交。
