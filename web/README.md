# SeeAlpha 独立前端

`app/`、`public/` 和根目录前端配置组成独立 Next.js / React 前端。
用户鉴权、Binance 账户、操作记录和 OLAP / ClickHouse 监控通过 [`../api/`](../api/README.md) 提供；预估资产 K 线目前返回示例数据。

## 前端启动

需要 Node.js >= 22.13.0 和 npm。先按 API 说明启动项目 API，再运行：

```bash
cd web
npm ci
cp .env.example .env.local
npm run dev -- --hostname 127.0.0.1 --port 3000
```

本机已安装依赖并配置 `.env.local`，打开 <http://127.0.0.1:3000>。
开发与生产构建均使用 webpack，修改页面后自动刷新。

浏览器只通过同源 `/api` 交互，前端不直接访问项目 Python 模块、数据库或本地业务文件。
服务端代理配置：

- `SEEALPHA_API_URL`：新 API 地址，默认 `http://127.0.0.1:8000`，承接鉴权、健康、账户配置、品种列表、余额、账户/仓位、操作记录及 OLAP / ClickHouse 监控接口。

前端请求转发到项目 API；生产构建同样需要设置目标地址，或由正式反向代理接管 `/api`。
正式部署采用同域 HTTPS，API 使用 Secure 会话 Cookie。

`npm run lint` 检查当前前端，`npm run test:frontend` 运行已有前端测试，
`npm run build` 构建生产版本。

## Python 管理端（兼容保留）

以下现有 Python 服务及任务模块保留到第二阶段迁移，仍可独立启动。
其文件口令登录与新 API 用户会话是两套独立机制，不作为当前 Next.js 前端的鉴权后端。

SeeAlpha 是基于 NautilusTrader 的多资产量化交易系统。本管理端当前提供项目检查、
策略回测、报告及任务管理；产品定位与各市场接入状态见 [项目首页](../README.md#产品范围与当前实现)。

在项目根目录启动：

```bash
.venv/bin/python -m web.server
```

默认监听所有 IPv4 网卡。本机打开 <http://127.0.0.1:8765>；其他设备访问
`http://运行机器的IP:8765`，也支持指向该机器的域名。
需要换端口时添加 `--port 8766`；按 `Ctrl+C` 停止服务及其正在执行的任务。
管理端使用 Python 标准库和现有项目环境，无需安装前端工具或升级依赖。

## 功能

- **总览**：项目检查结果、可用策略、研究报告及最近任务。
  页面每十秒读取已经发布的状态；分别显示各快照的时间，过期状态不能视为当前正常。
- **运维操作**：快速检查、完整检查。
  快速检查包括冻结来源与代码检查，完整检查额外运行全量测试。
- **策略回测**：BTC、ETH 的趋势跟随与均值回归多空入口，共八个选择。
  支持起止日期和 1m/5m 输入，使用策略现行参数。
- **报告中心**：检索已有单策略和组合回测报告，在新窗口打开原交互报告，下载参数和统计。
- **任务记录**：任务状态、输出日志、取消任务和打开新生成的报告。
  未启用 ORM 时任务记录保存在 `.local/state/web/jobs/`；启用后保存在业务数据库，
  日志仍保存在 `logs/web/`，重启后仍可查看。

回测日期以 UTC 为准，结束日不包含在内，每次最多 366 天。开始前会根据原策略要求
加载预热数据。只读取已有本地 Catalog，不自动下载或补齐数据；整个区间没有数据时
标记为跳过，部分数据缺失仍遵循现有回测行为，具体范围查看任务日志和报告。
结果统一保存到 `data/reports/backtest/<策略>/<run_id>/`，组合位于其 `portfolio/` 子目录。
每次使用独立运行目录；报告生成代码仍位于 `strategy_python/_report/`。

Web 端同时只运行一个任务，检查最多 30 分钟，回测最多两小时，超时会终止任务。
取消任务会停止该任务的子进程组，已产生的部分文件可能保留，不能视为完成的报告。
异常中断后，未完成记录标记为中断；不会自动恢复回测。

## 访问范围

默认 `--host 0.0.0.0`，可用 `--host 127.0.0.1` 切回仅本机访问，或指定某个网卡地址。
操作保留同源及页面请求凭证校验，允许通过网络 IP 或域名访问；只提供固定动作及报告文件，
不提供任意命令、文件浏览或密钥设置。

网络访问需要登录：用户名 `admin`，首次启动自动生成口令，保存在
`.local/config/web/access_password`（仅当前用户可读写）。可用 `--password-file` 指定
已有口令文件，口令至少 16 个字符。页面、接口和报告都需要认证；口令是登录凭证，
不要分享给无关人员。公网使用 HTTPS 反向代理保护登录口令传输。

跨网络访问还取决于 macOS 防火墙、路由器端口映射或反向代理。
监听所有网卡本身不提供公网地址。HTTPS 反向代理应保留原始 Host，
页面操作接受与该 Host 相同的 HTTP/HTTPS Origin，不信任转发头来绕过同源校验。

策略源码、冻结参数、采集启停、自动数据补齐及实盘下单不在此管理端的操作范围内。
研究策略和历史报告仍应按各自的研究说明解读。

## 验证

```bash
.venv/bin/python -m pytest tests/web -q
.venv/bin/python -m pytest -q
```

测试使用独立临时目录，覆盖输入校验、任务互斥与取消、异常退出、状态时效、请求来源
和文件访问边界。

## 模块边界

- `server.py`：HTTP 接口、访问控制、报告浏览及静态资源。
- `jobs.py`：仅供本管理端使用的后台任务、进程组、超时、取消和日志。
- `static/`：页面、CSS 和 JavaScript。
- `storage.py`：运行目录划分、启动互斥及旧目录迁移。

快速检查运行 Ruff 和源码基线测试；完整检查运行 Ruff 和全部 pytest 测试。
检查 worker 由任务管理器调用，不设置独立命令行或运行时目录。

## 运行文件布局与迁移

所有路径均以项目根目录为基准，不依赖启动时所在目录：

| 内容 | 路径 |
| --- | --- |
| 任务记录 | ORM 业务数据库；未启用 ORM 时为 `.local/state/web/jobs/` 的 JSON |
| 任务执行日志 | `logs/web/` |
| 默认登录口令 | `.local/config/web/access_password` |
| 服务互斥锁 | `.local/run/web/server.lock` |
| 回测报告 | `data/reports/backtest/`；启用 ORM 后索引存入业务数据库 |
| 项目检查结果与日志 | `logs/web/checks/` |

`.local/`、`logs/` 和运行数据均已由 Git 忽略。启用 ORM 后，旧任务 JSON 会自动复制到
数据库，原文件保留；同 ID 已有数据库记录时不会覆盖。日志、登录口令和服务锁保留在本机。
备份或迁移机器时，需要另行保留业务数据库或任务 JSON、日志及私有配置，不能只复制 `data/`。

升级后首次通过 `python -m web.server` 启动时，会迁移旧 `data/web_console/` 中
已识别的任务记录、日志和默认登录口令。先停止旧管理端；旧服务仍运行时会拒绝迁移。
迁移跨数据盘复制并校验文件，保留原口令，口令权限设为仅当前用户可读写。
同名文件内容不同则停止启动并提示冲突，不覆盖任一版本；修复问题后可重新启动继续迁移。
未识别的文件保留在旧目录，不自动删除。新旧目录都不存在时，不会为 Web 运行状态创建 `data/`。

服务锁在整个运行期间保持；旧目录的锁在首次迁移的服务停止后清理，空旧目录随之移除。
`--password-file` 可继续指定其他口令文件；迁移后的旧默认口令仍保存在上述私有配置目录。

## 项目操作记录

实时页和数据管理页的操作记录、同步按钮与操作 CSV 导出已切换为新 API 的
`/api/operations`，不再调用旧 trades/operations 列表。来源显示为项目、外部或
对账修正；真实成交与合成修正分开，历史覆盖信息随接口返回。
账户快照、人工调整和历史资产重建功能已移除；预估资产 K 线当前为示例数据。详见
[操作记录说明](../docs/OPERATIONS_API.md)。

旧版系统更新入口、页面及请求代码已移除；其 `/api/system/update` 路径在前端
返回 `410 Gone`，不再转发至兼容后端。

OLAP 连接配置、监控表和缓存存储在已配置的 ORM 业务数据库。OLAP 密码仍使用服务端密钥加密，迁移或更换机器时须保留密钥。新 API 启动后每分钟刷新监控缓存。
